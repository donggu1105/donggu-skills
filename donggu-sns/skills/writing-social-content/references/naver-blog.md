# Naver Blog Channel Reference

## 적용 범위

Blog의 네이버용 편집 분기다. `blog.md`의 사실 경계·문체·독립된 논지를 유지하고, 아래 차이가 있으면 이 reference를 우선한다. 공통 보이스와 페르소나 선택 계약은 바뀌지 않는다. 글만 작성하며 저장·이미지 작업·편집기 입력·게시를 수행하지 않는다.

## 출력 계약

1행은 제목, 다음 줄부터 Markdown 본문이다. 발행 대상은 Naver Blog이며 티스토리 원고와 별개의 초안으로 전달한다. Markdown은 집필 형식이지 SmartEditor 자동 변환 또는 현 발행기 지원을 뜻하지 않는다.

## 독자 질문에서 설계

- 글마다 답할 질문 하나를 먼저 잠근다. 예: FDE는 무슨 일을 하는가 / AX 도입 후 왜 안 쓰게 되는가. 검색량을 조회하지 않았다면 수요가 검증됐다고 말하지 않는다.
- 제목은 질문의 대상과 글이 주는 답을 드러낸다. FDE·AX 약어를 처음 쓰는 부분에서 필요에 맞게 풀어준다.
- 첫 단락에서 짧은 답 또는 다루는 범위를 제시하고 근거·판단으로 들어간다. 리드를 늘리기 위해 인삿말·개인 경험을 만들지 않는다.
- 소제목은 독자가 확인할 하위 질문이나 판단 단위로 둔다. 짧은 문단, 구체적인 근거, 반례·한계를 살린다.
- 기본 2,000~2,500자는 Blog의 편집 출발점일 뿐 네이버 노출 요건이 아니다. 질문에 충분히 답했다면 억지로 늘리지 않는다. 분량 조정은 장르와 사용자 요청으로 결정한다.
- FAQ는 본문이 남긴 질문이 있을 때만 쓴다. SEO 보너스라고 단정하지 않는다.

## 동일 소재의 채널 분리

티스토리의 자료와 사실은 재사용할 수 있다. 다만 네이버판에서 답할 질문, 리드, 설명 순서와 결말을 다시 잡는다. 단어 치환·문장 순서 섞기로 중복 탐지를 회피하려 하지 않는다. 동일 글 재게시가 무조건 검색 제재된다는 주장도 하지 않는다.

원문·인용·사례의 권리와 출처를 보존한다. 커뮤니티의 비공개 대화·참가자 정보는 공개 동의 없이 개인 글로 가져오지 않는다. 사용자 경험과 외부 인터뷰를 혼동하지 않는다.

## 링크·태그·독자 행동

- 필요한 근거와 실제 읽을 가치가 있는 관련 글만 연결한다. 아직 발행하지 않은 글의 URL을 만들지 않는다.
- 외부 링크가 있다는 이유만으로 검색 불이익을 단정하지 않는다. 커뮤니티 신청 링크는 해당 글의 목적일 때만 넣는다.
- 공개 태그는 본문과 직접 관련된 후보만 별도 전달 요청에 맞춰 제안한다. 내부 분류명·운영 태그는 공개 본문에 넣지 않는다. 정확한 발행 태그 확정은 `publish-sns`의 미리보기 영역이다.
- 발행 주기·키워드 반복 횟수·사진 수·글자 수를 순위 공식처럼 제시하지 않는다.

## 검수

1. 제목과 첫 단락이 같은 독자 질문을 다루는가.
2. 원문에 없는 현장 경험·수치·성과가 들어가지 않았는가.
3. 티스토리/다른 채널과 별개의 읽기 경험이며, 재편집 이유가 독자 편의인가.
4. 사례의 공개 권한과 원출처가 확인됐는가.
5. 문체는 장르와 사용자 목소리를 보존했는가. 네이버라는 이유로 무조건 해요체로 바꾸지 않았는가.
6. 작성물과 실제 발행기 지원 범위를 구별했는가. 미지원 서식을 조용히 지우지 않았는가.
